# 対象機能と完成条件

## 目的

紹介会社と求人企業の双方が、同じ推薦案件を安全に共有して選考を進められることを、ブラウザ操作で確かめられるOSSプロトタイプを作る。コードだけでなく、導入・操作・設計の読み方をそろえ、第三者がローカルで再現できるものにする。

## v0.1の機能

| ID | 機能 | 完成時の動作 |
| --- | --- | --- |
| F01 | ログイン | OIDCで本人を識別。1ユーザー1組織、組織切替なし。ログアウトでセッション失効 |
| F02 | 求人登録・検索 | 企業が自社求人を下書き・公開・募集終了。紹介会社は公開求人を検索 |
| F03 | 求人保存 | 紹介会社内でお気に入りを共有。候補者情報を含まない |
| F04 | 候補者登録 | 紹介会社が自社の架空候補者を作成・更新・アーカイブ |
| F05 | PDFレジュメ | 架空の静的PDFを検査して登録。最大10MiB/20ページ、注釈・フォーム等の制限は安全性設計を参照。認可後に閲覧 |
| F06 | 推薦 | 公開求人へ候補者と選択したPDFのスナップショットを提出 |
| F07 | 選考 | 求人企業が選考・不採用・採用決定を記録。紹介会社は辞退・共有撤回。進行中の撤回は辞退と同時処理 |
| F08 | 通知モック | 状態変更の通知予定を画面で閲覧。「未送信のデモ」と明示 |
| F09 | 請求書プレビュー | 採用決定案件から固定1明細・固定額のA4縦1ページPDFを生成しブラウザ表示 |

候補者本人のアカウント、自己登録・招待画面、メッセージ、面接日程、ATS・会計連携、決済・入金、データ移行、AI推薦はv0.1の対象外。紹介会社・企業のアカウントと唯一の所属はデモ環境の初期データで作る。複数所属/組織切替は対象外。

## 架空データ

紹介会社A/B、求人企業X/Yの4組織と、各組織に専属の利用者を1名ずつ準備する。架空求人8件、架空候補者6名、推薦状態の異なる案件、サンプルPDFを含める。メールアドレスはexample.com等の予約ドメインを使う。

名前、経歴、企業、住所、レジュメはすべて架空。アップロード前に架空データであることを確認するUIを出す。共用の公開デモには任意ファイルのアップロード機能を公開しない。初期版は自分のローカル環境で試す方式。

## 一巡の完成条件

企業Xが求人を公開し、紹介会社Aが候補者とPDFを登録・推薦する。企業Xがその推薦のみを確認して採用決定し、AとXがデモ請求書PDFを表示できる。紹介会社Bと企業Yには候補者・推薦・文書・PDFが見えない。

画面更新後も状態が保持され、ログアウト・再ログインで続きから操作できる。別組織のIDへのアクセス、競合更新、重複送信を処理し、失敗は利用者が理解できる文言で返す。

## プロトタイプと運用判断

認証と組織分離はプロトタイプでも実装する。実在の候補者情報を扱う運用に進むには、同意、保存期間、削除・開示、障害対応、バックアップ復旧、監視、契約と法的位置づけを利用者の運用に合わせて決める。これらはプロトタイプ完成だけで満たされたとは扱わない。
