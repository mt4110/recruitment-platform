# S0の確認条件と停止条件

2026-10-16 / 設計v0.5 改訂1 / **S0実施済み・両arch成立、S1未着手**

本書は[安全な書類経路](12-secure-document-pipeline.md)のS0だけを具体化する。以下は承認時の確認条件を保存した計画。後続の明示承認でS0を実施し、[実施記録](../validation/2026-10-16-s0-report.md)へ結果・未検証・工数影響を保存した。製品変更/移行/公開は実施していない。

## 1. 目的と実行前条件

確認するのは、標準暗号の相互運用と鍵復旧、鍵を持つbrokerから不信parserを隔離できる構成、PDF/Sheetsの限定表示、暫定資源制限下での成立性。製品APIや移行の完成判定ではない。

- オーナーがS0の範囲と作業枠を別途承認する。提案枠は**8〜14時間**、8時間時点で中間報告、承認上限または14時間の早い方で停止。上限延長を推定しない。
- 通常デモ3000と既存DB/volume/鍵を変更しない隔離projectを使う。合成文書とテスト専用鍵のみを使い、実在情報/実鍵を持ち込まない。Excel契約・Googleの新規外部共有は不要。
- 対象は既存のmacOS/Apple Silicon上Linux/arm64とCIのLinux/amd64、既存Chromium。両archで必須の確認を行い、CI未実施は完了ではなく未確認とする。新しい全OS/ブラウザ対応へ広げない。
- ローカル暗号ハーネス/コンテナ設定は将来`validation/`等へ製品から分離して置く。loopbackのWeb Crypto確認に既存の開発用HTTP例外を使う場合は記録し、TLS終端/IP制限の公開確認済みとは扱わない。外部通信は既知依存の取得以外は停止し、実文書を外部スキャンサービスへ送らない。
- 解析候補のversion/digest・license・既知脆弱性/利用経路を読み、到達可能な重大問題を回避できない候補は不採用とする。M6全体の監査残件をS0で解消した扱いにしない。
- 資源上限・期待値・fixtureの由来を試験前に記録する。テスト鍵/証拠はGit外と匿名化済み公開証拠に分け、鍵・ticket・原本本文をログ/スクリーンショットへ出さない。後日削除が必要なら具体的対象について承認を得る。

## 2. 実験開始時の安全上限

以下は未計測の**暫定打切り値**であり、性能保証や許可範囲を満たす実績ではない。変換が収まらなければ未成立を報告し、結果を通すために無断で上限を緩和しない。

| 対象 | 初期上限 |
| --- | --- |
| 同時処理 | 全体1ジョブ、ブラウザ暗号化1件。複数投入は直列キューで確認 |
| 入力/暗号payload | 原本10MiB、metadata4KiB+長さ4byte、GCM tag16byte、外側envelope8KiB。申告値だけでなく実長も確認 |
| broker | 1CPU、512MiB、64PID、個別呼出しwall30秒。原本/成果物のnative parserを同居させない |
| 構造検査 | 既存の256MiB/CPU5秒を維持し、wall10秒で停止。PDF20ページ、XLSX ZIP64MiB/1entry16MiB/1,000entry/20sheet等の既存上限も維持 |
| 変換sandbox | 2CPU、1GiB、64PID、CPU30秒/wall60秒、tmpfs256MiB。作業中の書込み先もtmpfsに限定し、枯渇時は失敗 |
| PDF画像 | 目標150dpi、1ページ辺長4,096pxかつ8M画素以内、全文書80M画素以内。超過時に無断で縮小せず変換不可とする |
| 成果物 | PNG1枚8MiB、画像合計64MiB、抽出テキスト/正規化表は各1MiB、manifest256KiB。計算済みサイズも検証 |
| XLSX表示 | 20,000セル、1セル32KiB、正規化テキスト1MiB、巨大な空矩形を展開しない |
| 隔離project全体 | 合計4CPU/4GiB、全scratch512MiB、実験用暗号blob/成果物合計512MiB。容量不足時は追加ジョブを止める。既存デモのCPU/メモリを減らさない |

brokerの30秒は復号・転送・暗号化の**個別呼出し**に適用し、AV/構造検査/変換を待つ全ジョブへ重ねない。独立したステップのタイムアウトとジョブ全体wall120秒を持つ。制限値を超える候補では自動retryしない。特に大きなページやXMLを解析する前に、入力上限とOS/コンテナ制限が有効なことを確認する。

## 3. 必須確認と証拠

fixtureは既存の架空PDF・現行R1のSheets実出力2点（e2e/fixtures、画像修正後にSheetsへ再import/export済み）と最小合成fixtureを使用する。旧R0のPNG CRC不正試料は正常入力に流用せず負例として保持する。元ファイル/hash/由来、期待値、拒否理由を実行前にmanifestへ記録する。原本/鍵そのものは公開証拠に載せない。

| ID | 入力・確認 | Passの条件 | 残す証拠 |
| --- | --- | --- | --- |
| S0-I | broker/relay/sandboxの別identity/PID/mount/network、FD/secret/proc、ジョブ間tmpfs | sandboxからbrokerの鍵・blob・DB・API・外部/他ジョブへアクセス不可。許可relayだけ到達し、権限拡大/host管理socketなし | 設定/digestと匿名化した許可・拒否probe結果。設定読取りだけでPassにしない |
| S0-C | Web Crypto→brokerと成果物→閲覧担当の相互復号。小ファイル/10MiB、別page/種別/版、AAD/ciphertext/tag/wrapped DEK改変 | 正常bytes/hash一致、各改変/別contextを拒否し認証前平文を後段/配信へ渡さない。成果物ごとの鍵/nonceと再生成世代が分離 | テストvectorのhash、件数・結果・例外分類。秘密値なし |
| S0-K | 原本鍵/成果物鍵それぞれの旧版、ローテーション、欠落/失効、backupからの復元 | 旧未失効版だけ復号可、欠落/失効で拒否、復元後のbytes/hash一致。brokerは成果物private keyを持たず閲覧側は原本private keyを持たない | 鍵ID/版と状態/復旧結果の対応表。鍵データなし |
| S0-P | 通常/タグ付きPDF、20ページ、長い日本語、文字抽出不能fixture、既存禁止要素/破損、過大ページ/出力・時間上限 | 正常でページ数/内容を維持。日本語とページ順を目視。抽出不能は明示。禁止原本は変換前に拒否、超過は制御した失敗で原本fallbackなし | 出力hash/サイズ/ページ数、匿名化画像、目視記録、拒否理由、制限発動結果 |
| S0-X | Sheets実出力2点＋型/日付/結合等の合成fixture（下記） | 固定した期待値と一致。数式非実行・保存値注意、非表示部分/省略画像の明示、未知/不正/上限超過で制御した失敗 | セル座標と期待/実値の比較、画面、拒否分類。任意HTML/URLへ変換しない |
| S0-R | 正常/上限境界/超過と停止、warm/cold、2件の直列投入 | 超過を上限内で停止、別ジョブ/通常デモへ波及しない。失敗は利用不可。時刻/ピークメモリ/容量/終了理由を取得できる | arch・ホスト/VM・制限・生の計測値・失敗数。性能達成率は捏造しない |
| S0-D | 候補依存のversion/digest、license、監査と既知制約、受信状態/切替の机上照合 | 必須方式ごとに候補と未解決を列挙。新たに持ち込む配布条件が確認できない場合は候補未成立 | 依存一覧/公式出典、採否理由、旧設計との差。M6完了と混同しない |

S0-Xの最小合成fixtureはshared/inline/保存文字列、boolean/空欄/数値・精度、標準日付14〜17の1900/1904系・serial59/60/61、時刻/独自書式の未変換、cached値有/無/エラー、結合/交差、非表示sheet/row/column、画像省略、ISO日付型t=d/未知型、無効参照と表示上限。既存Sheets2点だけで型別互換を一般化しない。実際のExcel保存との互換性は未確認のまま。

S0-Rは環境/入力を固定し、各正常ケースをcold1回とwarm3回程度で分解記録する。暗号化/受信相当/AV等の既存処理/変換/復号表示のどこまで測ったかを区別し、未接続の段階は未計測とする。少数回からp95や商用SLAを主張しない。本番API経路・受信再試行/lease/7日照合の実動作、負荷分布、AV更新障害の製品回帰はS1〜S5へ残す。

## 4. S0で実装しないもの

予約/ticket/受信API・新DB migration、常駐製品ジョブ、既存書類の移行、R5端末永続化、クラウド/KMS/TLS/IP公開、ツール実adapterは作らない。暗号/変換/隔離を評価する最小ハーネスだけを将来のS0実作業候補とする。受信状態は設計表の中断点を机上で追い、実装成功と報告しない。

ハーネスの暗号・復旧やsandboxの成功を、製品全経路/全依存の安全性やS-A01〜S-A10完了へ読み替えない。正常/拒否fixtureを都合よく変更してPassにしない。

## 5. 時間配分と判定

| 区分 | 内容 | 仮積算 |
| --- | --- | ---: |
| A | 依存/隔離構成とアクセスprobe、初期上限の確認 | 2〜3時間 |
| B | 原本/成果物の相互暗号・旧鍵/失効/復旧 | 2〜4時間 |
| C | PDF/Sheets/合成型fixtureの変換・表示と資源境界 | 2〜4時間 |
| D | 両archの照合、計測/証拠/制約・後続工数の再積算 | 2〜3時間 |
| 合計 | S0のみ | **8〜14時間** |

S0-I/C/K/P/X/R/Dの必須行が両archで成立し、証拠と失敗条件を記録したときだけ「S0成立」とする。一部未実施は未確認、意図と合わない結果/安全条件の不足は未成立とし、理由・代案・必要工数を報告する。代替方式の試行は残り枠内かつ同じ安全条件を満たす場合に限定する。

鍵露出・sandboxから禁止先へ到達・上限無効・通常デモへの影響を検出したら、その実験を直ちに停止する。時間枠内でも解消不能なら該当候補は未成立。独立した他行の確認は安全が確保できる範囲だけ進める。

S0成立後もS1へ自動着手しない。測定環境と入力、候補採否、未確認事項、原本/成果物鍵の管理負担、追加74〜126時間の各残行への影響を報告し、次の範囲をオーナーが判断する。
