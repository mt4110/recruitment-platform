## 設計判断

- プロトタイプの求人は自身のDBが正本。外部求人連携や移行を必要とせずに動く。
- 組織ごとの候補者と、求人企業へ推薦した情報を別テーブルにする。
- 認可はRust APIとPostgreSQL RLSで実施する。UIの非表示だけに依存しない。
- 通知はDB内の送信予定記録まで。請求は実際のPDF生成まで、外部発行や入金処理は扱わない。
- OIDCの認証基盤はローカルで起動できる。独自のパスワード認証は作らない。
- 初期機能を変更するときはscope、API、DB、権限、受入条件を同じ変更で更新する。

未決のパッケージバージョンとライセンスは、[実装前に解決する項目](07-delivery.md)で管理する。クラウドのIaCコードとLP本文は後続成果物。
