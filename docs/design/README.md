## 設計判断

- 利用者は1ユーザー1組織。組織切替UI/APIを持たない。
- プロトタイプの求人は自身のDBが正本。外部求人連携や移行を必要とせずに動く。
- 組織ごとの候補者と、求人企業へ推薦した情報を別テーブルにする。
- 認可はRust APIとPostgreSQL RLSで実施する。UIの非表示だけに依存しない。
- 企業の候補者・PDF閲覧はE_SHAREDに統一。共有参照は推薦時に保存し、原本の権限を拡張しない。
- 求人編集/募集終了と提出は同じ求人のtransaction-level advisory lockで順序を固定する。
- 通知はDB内の送信予定記録まで。請求PDFは固定1ページ・1明細。
- OIDCの認証基盤はローカルで起動できる。独自のパスワード認証は作らない。
- 初期機能を変更するときはscope、API、DB、権限、受入条件を同じ変更で更新する。

[初回6件・再レビュー3件の修正対応表](../reviews/2026-10-15-design-revisions.md)で変更箇所と実装時の確認条件を追えます。[再レビュー記録](../reviews/2026-10-15-design-rereview.md)は修正前v0.2時点の判定として保存します。計画工数は**80〜140時間の仮積算**で、予算承認や納期の確約ではありません。

未決のパッケージバージョンとライセンスは、[実装前に解決する項目](07-delivery.md)で管理する。クラウドのIaCコードとLP本文は後続成果物。
