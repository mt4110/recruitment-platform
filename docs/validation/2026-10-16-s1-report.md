# S1 署名付き・暗号化受付の実装記録

状態：**S1完了**。S2には進まない。

今回の承認範囲はS1実装・E2E・CI・コミット／push。S2、R5、外部公開は対象外。

## 実装範囲

- Local受信API：受付予約、attempt作成、署名ticket発行、暗号文PUT、complete、状態照合。
- ブラウザWebCryptoのAES-256-GCM（96bit nonce／128bit tag）、RSA-3072 OAEP/SHA-256によるDEKラップ。ファイル名は最大4KiBの暗号化メタデータ内に置く。
- ticketはHMAC-SHA-256。用途・audience・PUT・受付／attempt・保存先・暗号文hash／長さ・envelope hash・版・期限を束縛する。現在のログイン、固定所属、Origin/CSRFも必要。
- 5分ticket、初回認可から15分／初回予約から24時間の上限。再暗号化は新attempt・DEK・nonce・AADとし、旧attemptは閉鎖する。
- 組織の未完了受付10件／100MiB、物理保存1GiB（既存領域を含む）、ディスク空き256MiB以上。閉鎖attemptの孤児データも予約容量に残し、自動削除しない。
- 単一Local受信プロセスがvolumeのOSロックを保持。受信lease・fencing、create_new、暗号文fsync、完了manifestの原子的公開・ディレクトリfsync、DB確定の順。受信は合計5分／無通信30秒。
- 停止したwriterのmanifest・実バイト・hash・token・期限を照合し、storedかclosedへ復帰する。不確かな受領を新attemptで上書きしない。
- completeは一つのcanonical attempt、pending書類、暗号化参照、一つの後続jobを同一DB transactionで確定。202は業務処理の完了ではない。
- 結果保持は既存idempotency_recordsが正本。ready／rejectedから7日間、期限後は同じキーを再実行できない。
- R4の暗号化下書きに操作キー・選択情報を保存し、再起動時は受付結果から復帰する。File本体・DEK・ticket・暗号文は永続化しない。R5は未着手。

## 具体化したデータ契約

予約時はupload_sessionsのdocument_idを確保し、complete時にdocumentsへpending行を作る。復号前の原本名・原本hashを仮の値で埋めずNULLとし、encrypted_transportの制約でpending・未検査を強制する。画面には中立名「暗号化書類（検査待ち）」を表示する。S2で原本メタデータを確定するための追加migrationが必要。

APIにはラップ用公開鍵だけをmountする。秘密鍵は.localのホスト側0600ファイルに置き、API／Nextへmountしない。ticket鍵と下書き鍵は別に生成する。S1は初期鍵版のみ。鍵broker、永続的失効・ローテーション、復号・AV・変換・安全な閲覧はS2以降。

新規アップロードUIは暗号化受付を標準にする。S1とS2の間も既存デモの一巡を確認できるよう、明示的に解除した場合だけ旧平文検査経路を残す。既存回帰試験はこの経路を明示して確認する。**製品全体の平文原本経路を閉じた状態ではなく、外部公開・実情報利用は承認しない。** 旧原本／請求PDF経路の閉鎖はS3/S4の契約のまま。
