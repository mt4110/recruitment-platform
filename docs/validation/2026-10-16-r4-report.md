# R4 個人下書きAPI・暗号化・サーバー保存と復元

2026-10-16。R4のみを対象とし、R5・M5へは進まない。検証対象commitは `b8e7c8f2eafdb18878979329fa65b2121ae629ef`。最終arm64実行とLinux/amd64 CIがともに成功し、R4を完了した。

## 実装

- `form_drafts` / `draft_mutations` / `draft_operations` / `draft_keys` / `draft_admissions`を追加。ENABLE/FORCE RLSでorgと本人の両方を分離する。本人が同じ組織へ所属していても別ユーザーの下書きは読めない。所有・種類・対象は変更不可。求人/候補者の対象org FK、application参照FKとAPI側の関係認可を併用する。
- 12種の現行フォームを許可リストで検証する：求人新規/編集、候補者新規/編集、推薦新規/理由、提出書類の選択、選考/辞退/共有取消の理由、書類受付metadata、求人/候補者/推薦の検索条件。ログイン情報・CSRF/token・同意済みフラグ・File bytes・任意URL/HTMLは保存しない。空/途中入力は保存可能とし、業務確定時の必須条件は維持する。
- `GET /drafts`（metadataのみ）/ `GET /drafts/:id` / `PUT /drafts/:id` / `POST /drafts/:id/discard` / `GET /drafts/:id/outcome?operation_id=` / `POST /drafts/key`。書込みは認証/Origin/CSRF必須、全応答no-store。毎回現在の対象権限・状態・版・参照先を照合する。共有失効後の企業側自由記入理由は復元しない。
- サーバーpayloadをAES-256-GCMで暗号化。新しい96bit nonce、origin/org/user/draft ID/種類/対象/schema/base版/revision/key版をAADに含める。独立したGit外`DRAFT_MASTER_KEY`からHKDF-SHA256でserver-payload/key-wrapの用途を分離する（[RFC 5869](https://www.rfc-editor.org/rfc/rfc5869)）。既存暗号文を復号できない場合はPUTでも上書きせず503にする。本人用の端末鍵はmaster派生の別鍵でwrapし、競合生成を直列化する。端末用の鍵をUI/端末ストレージに保持する実装はR5に残す。
- 1draft plaintext 64KiB、draft route要求96KiB、他の既存JSON routeは64KiB。本人の有効draft 50件/2MiBまで、新規30件/時、更新120件/分。429/Retry-Afterとquota409を返し、入力を消さない。7日TTLは成功保存時のサーバー時計で決める。
- draft IDをブラウザで生成し、PUTのrevision CASとmutation IDで応答喪失/競合を扱う。厳密な同要求は24hの結果参照を返す。期限/破棄/consume済みは同IDで再作成できない。消費/破棄時は暗号文をNULLにし、最小tombstoneを保持。期限切れ暗号文の自動整理・物理削除は実装/実行しない。
- 求人/候補者の作成・PATCH、推薦作成/理由/提出、選考/共有取消は`draft_id/draft_revision/operation_id`を受け取り、入力との対応を検証して業務更新・consume・結果参照台帳を同一transactionに記録する。POSTはIdempotency-Keyとoperation IDを一致させる。既存APIとの互換のため3項目全省略は許可し、一部省略は拒否する。フォーム以外の公開/アーカイブ/お気に入りボタンは既存契約を維持する。
- 操作lock→既存冪等lock→業務lock→draft lockの順を維持する。業務変更後にdraftが競合していた場合もtransaction全体をrollbackする。7日間の操作結果を通常24hの冪等記録より先に照合し、期限後も同操作を新規実行しない。後からdraft連動項目を省略した旧形式の要求でも、同じPOSTキーにdraft操作記録があれば拒否し、24h超の新規再実行へ戻さない。結果のPII本文を台帳へ複製しない。

## フォームの動きとR5との境界

入力後500msのdebounce、連続入力中は2秒を目標にサーバー保存する。最新内容を直列化/coalesceし、曖昧な保存応答は元mutationを先に照合する。確定前には最新保存を待ち、成功したrevisionを送信する。未同期/保存失敗時は業務確定を止める。確定した4xxでは古いpending要求を解放して修正入力の保存へ戻り、結果不明の通信断/5xxは同mutationで先に照合する。429のRetry-After期間は新しい送信を控える。

再表示時は本人の保存済み下書きを復元する。複数候補は種類・保存時刻・短縮IDで本人が選ぶ。確認項目は未確認に戻す。保存中/未同期/成功/失敗を区別する。競合時は自動merge/上書きせず、現在の入力を残して比較し、「最新から再開」「自分の入力を確認して適用」を選べる。業務の版が変わった場合に本人が最新情報を読み直したときは、新しいdraft IDを使い、以前の下書きを上書きしない。

書類受付は候補者編集から独立して保存する。ファイル選択前の書類種類だけの変更も保存・復元する。原本登録前に操作キー・種類・名前・hashを保存し、再表示では受付結果を自動照合する。既存IDがあれば再アップロードせず復帰する。未受付の元ファイルを再選択する場合は名前/hash/種類を照合し、元キーで再送する。処理待ち/未照合のキューがある間は後続送信を止める。R3の復帰リンクが別の保存済みキューを指す場合は元キューを上書きしない。

認証失効時はフォーム・理由・検索条件・File参照・表示中の平文を破棄する。保存済みの本人下書きは再認証後に復元できる。最後の未同期入力を保証するものではない。旧M2/M4の「認証失効後も平文入力を表示する」試験は、R4の破棄契約に合わせて入力が空で操作拒否となることへ更新した。業務version競合時に入力を維持する条件は弱めていない。

**R5のIndexedDB暗号化永続化、未同期端末キュー、通信断からの同期、端末鍵の旧版再暗号化/失効、同一profileの再起動復帰は未実装。** R4の復元は通信でき、サーバー保存が成功した内容が対象。File bytesは後続でも保存しないため、未送信ファイルは再選択する。サーバー復元/保存をブラウザローカルの耐久保存と呼ばない。

## 設定と起動

新規setupは独立したDRAFT_MASTER_KEYを生成する。既存envに鍵がない場合、稼働中の既知DBが下書き表のない旧版であることを確認したときだけ追加する。既存draft DBの鍵を失った場合やDB状態を確認できない場合は停止し、代わりの鍵を生成しない。`.local/local.env`とDB/volumeをセットで保全する。今回、既存通常デモへのmigrationや新コード反映、原本/volume/証拠の削除は行っていない。

## 検証

Browser plugin not available。既存Playwrightの隔離環境で確認する。主経路は候補者入力→自動保存→再表示/本人復元→明示確定→consume→古いPUT拒否。並行タブ、共有失効、upload metadataの独立性を併せて確認する。ブラウザcontextの再表示はR5のオフライン/同一profile電源断試験と区別する。

Rust単体2件：RFC 5869テスト値（32byte出力）、AES-GCM round trip・別AAD/鍵・改ざん・不正nonce長の拒否。builderで`cargo test --locked --release drafts::`を実行し、失敗時はimage buildを止める。

追加E2E12件：本人/組織のAPIと直接RLS、同一組織の別本人、暗号文・nonce/未知項目・型/長さ/no-store、mutation再送/2更新競合/期限切れ/破棄/改ざん、業務確定と24h超の7日結果照合、誤revision/入力対応のrollback、フォーム復元と確認未復元、12schema/現在権限/共有失効、wrapped key/生成競合/失効、quota/頻度/大きさ、2タブ比較・明示適用、認証/Origin/CSRF/未対応schema、候補者編集と独立したupload復帰/元キー再選択、ファイル選択前の種類だけの保存/復元。

### 途中の失敗と修正

最初の局所試験はTypeScriptのcallback内narrowingを修正した。複数下書きがある画面復元は、選択肢を区別する短縮IDと未同期表示を追加し、サーバー保存の対象値を確認してから本人が選ぶ形で再検証した。

初回全件で検索復元の再読込ループ、draft競合を接続エラーとする表示、受付の再表示時に照合を待ったまま新規送信できない動き、認証失効後の旧試験の期待値を検出した。復元の起動条件、エラーcode保持、受付の自動照合、認証後の平文破棄を修正した。暗号文が復号できないPUTの上書き防止、旧形式への連動項目省略による24h超の同キー再実行の拒否、入力検証422後に訂正して自動保存へ戻る処理も追加した。

対象回帰は50/51成功。残りは並行受付時の単一AV worker混雑503で、採番と検査成功を混同した期待だった。503はSCANNER_UNAVAILABLEかつ同一IDがpending/配信不可であることを必須にし、元IDの再検査で合格するまで確認するよう修正した。retry設定や配信条件は緩めていない。途中の失敗や対象回帰の成功だけを最終全件の受入には使わない。その後の全件は87/88成功で、旧XLSX画面テストが一覧と受付キューの「登録完了」を同時に拾った。書類一覧に探索範囲を限定し、実際の完了状態と他の安全条件は維持した。最終対象以外のCI 38835558180 / 38837210856 / 38838204473 / 38838424651は打切った。acaf6f2のarm64全88件は成功したが、同ソースのCI 38838791053は自動照合中の無効なinputへ早くfocusした旧M3試験1件が失敗（87/88成功）。書類入力と種類選択のfocus前に有効化を待つ条件をそろえ、focus成功自体は引き続き必須とした。待機条件をまとめる前のCI 38840210728、および書類種類の単独保存を追加する前のCI 38840352987は打切り。旧ソースのローカル実行もSIGINTで中止し、runnerのfinallyでその隔離サービスだけを停止した。
