## 判定と範囲

**S0はarm64・Linux/amd64の両archで成立。最終CI全体も成功。** 実行ソース12ファイル、native Sheets入力のSHA256、受入結果を照合し、暗号化回収したnativeの5画像も目視確認した。製品の署名upload/API/DB migration/常駐ジョブ/既存書類移行/R5、クラウド、公開は実装していない。S1に進まない。

最終CIソースは`67a22db020fcae630396f8207ca6c67d222ad455`。local実行時のGit HEADは`68bedbd`だが、陽性対照追加後のハーネス全11ファイルをSHA256で実行前後に照合した。追加の目視証拠暗号化helperは別途ローカルで5画像のroundtripを確認し、そのSHA256も記録した。CIは合計12ファイルを収録する。後続の記録commitを製品コードの検証対象と取り違えない。

手順：[S0ハーネス](../../validation/s0/README.md)、計画：[S0の確認条件](../design/13-s0-verification-plan.md)。Linux CI：[38862481187](https://github.com/mt4110/recruitment-platform/actions/runs/38862481187)。結果は[arm64証拠](s0-2026-10-16/arm64/summary.json)、[amd64証拠](s0-2026-10-16/amd64/summary.json)、[比較結果](s0-2026-10-16/comparison.json)を参照。

## 確認中に判明したこと

1. **日本語CMapを同梱する。** 元の依存imageでは`UniJIS-UCS2-H`が見つからず日本語が欠落した。S0 imageに`poppler-data=0.4.12-1`を追加後、日本語の画像・抽出文字を確認した。依存の追加はS0だけで、製品imageは未変更。Poppler/Adobe CMap等の配布条件をM7に残す。[Ubuntuのpackage情報](https://packages.ubuntu.com/noble/poppler-data)
2. **Sheets正常fixtureは現在のR1実出力を使う。** 旧R0の2点にはPNG CRC不正があり、現行validatorは意図どおり拒否する。R1で画像を修正してSheetsへ再import/native exportした`e2e/fixtures`の2点を正常入力にした。今回ファイルを修正したり検査を緩めたわけではない。[既存R1の修正記録](2026-10-15-r1-report.md#検出修正した問題)と`e2e/fixtures/provenance.json`を参照。Excel実出力は引き続き未確認。
3. **請求PDFとレジュメのpolicyを混ぜない。** 既存M5請求PDFはレジュメの構造数上限でOBJECTS拒否。合成の静的日本語PDFを正常入力とし、M5ファイルは拒否ケースにも残した。請求生成を別の信頼済み経路にする設計を維持する。
4. **Dockerの自動network poolが枯渇していた。** 既存networkを削除せず、使用CIDRと衝突しない`10.240.0.0/16`内の小さな`/28`を各実験に割り当てた。通常デモ/VM容量/CPU/memoryの設定は変更しない。
5. **ハーネスの修正と製品修正を分けた。** 非rootのfixture読取り権限、tmpfs証拠の稼働中回収、日本語CMap、20ページfixtureの独立ページ生成、layout抽出の空白を許すページ番号照合、非表示sheetの対象を限定したDOM検査を修正した。正常/拒否期待値・容量/形式policyを弱めず、修正後の一巡を採用した。初期失敗は`.local/s0-arm64-attempt*`に保持した。

## 性能と資源の読み方

arm64の10MiB合成入力4回はブラウザ処理**210〜229ms**。これは暗号化だけでなくframe作成・鍵import/wrap・base64化を含む。fixture HTTP+ホストIPC+broker復号は**約335〜356ms**。Docker内部networkだけではホストへportを公開できないため、信頼したホスト制御ハーネスが`docker exec`で橋渡ししている。アプリ/relayにDocker管理権限は与えていない。

同環境の合成日本語1ページは構造検査/画像化/文字抽出を含め約0.21秒、20ページは約1.44秒。成功PDFで記録したcgroupピークは最大約54.1MiB。資源発動probeのピークは約271MiBで、tmpfs容量超過も含む。条件と生値は[暗号計測](s0-2026-10-16/arm64/crypto.json)、[PDF/XLSX](s0-2026-10-16/arm64/cases.json)、[資源](s0-2026-10-16/arm64/resources.json)を参照。

amd64はハーネス約91秒で完了。arm64約106秒も含め、人の開発工数ではない。native側のcomponent計測は同じ証拠構造で保存している。

少数の合成入力によるcomponent測定であり、商用p95/SLA/製品速度ではない。実upload、認可、AV/queueの製品結合、storage/KMS、WAN、業務共有による遅延を含まない。1GiB cgroup OOMや64PID枯渇まで実行したわけではなく、実設定と低い子RLIMIT/timeoutの発動を分けて記録した。

## 依存監査と既知制約

候補はpikepdf10.17.0、Pillow12.3.0、Poppler24.02.0、poppler-data0.4.12-1、Node24.22.0、Playwright1.64.1/Chromium156。arm64の候補経路のHigh/Critical検出は0、image全体の指摘は**arm64 662件・amd64 670件（package/advisoryの検出数）**。未修正・非利用経路の指摘も[qualification](s0-2026-10-16/arm64/qualification.json)へ全件保持した。両archとも候補経路のHigh/Critical検出は0。名前による候補抽出とldd経路確認は、完全な到達性解析ではない。既知問題の未検出や独立監査済みと説明しない。

Poppler/GPL、CMapデータ、pikepdf/MPL、Pillow、Nodeの同梱条件、Chrome for Testingのバイナリ規約は最終配布時に照合する。image自体を公開していない。M6の監査保留を解消した扱いにしない。

復号候補は今回確認したNode/OpenSSL。既存Rust依存の`rsa`を秘密鍵復号へそのまま流用しない。[RUSTSEC-2023-0071](https://rustsec.org/advisories/RUSTSEC-2023-0071.html)は2026-10-16確認時もpatched versionなしで、既存の公開鍵検証だけの利用評価を秘密鍵処理へ拡張できない。製品の暗号境界/エラー応答・依存選定はS2で改めて確認する。

- 鍵復旧/失効はfixture serviceでの確認。製品の永続失効台帳、KMS、災害復旧を実装していない。
- 検査と暗号をcomponent単位で確認した。実AVを含む製品ジョブ連携はS1〜S5で確認する。
- XLSXは表・保存値の限定表示。画像/図形/罫線/完全レイアウト、Excel実出力、全ブラウザ/実機は対象外。
- localhostのHTTP例外でWeb Cryptoを実行。TLS/CDN/固定IP公開を確認したわけではない。
- nativeの目視証拠5画像は、所有者のRSA3072公開鍵でwrapしたAES-256-GCMの暗号化artifactとして回収する。復号秘密鍵は手元の`.local/s0-proof-private.pem`だけに保持し、CI/Gitへ送らない。公開鍵だけをworkflow inputへ渡す。これは目視証拠の保護で、製品uploadの実装ではない。
- 原本/鍵/正規化内容/本文入り画面/生の監査はGit外`private/`に保持。公開証拠は本文を含まないJSON・status画面・依存経路に限定する。

## 証拠・目視・環境保全

- 実行コードとhelperを合わせた12ファイルが一致し、実行中の変更なし。合成PDF/ZIPはrunごとのmetadataを含むためbyte一致を要求せず、固定期待値/拒否結果を照合した。`cases.normalized_sha256`は時間等を含むworker結果のhashで、純粋な表示内容のarch間比較hashではない。
- arm64とamd64の日本語1ページ・ページ20・型別表・履歴書/職務経歴書の限定表示を目視確認。原本の画像/レイアウト完全再現は検証していない。
- Browserプラグイン未提供のためPlaywrightを使用。1280×800でpage identity/blank/console/pageerror、暗号操作と非表示部分を開く操作を確認。frameworkを使わない独立ハーネスで、製品のUI回帰ではない。
- source/public証拠のTrivy secret検査は0件。生の鍵・本文・画像は公開していない。通常デモの7サービスはhealthy、HTTP200を維持。S0のrole/jobはすべて停止、既存DB/volume/鍵・VM設定は変更なし。テスト用の停止container/network/鍵volumeと初期失敗は保持している。
- 初回CI [38861682962](https://github.com/mt4110/recruitment-platform/actions/runs/38861682962)も成功。陽性対照と暗号化目視証拠を含む上記最終CIを正式証拠とする。

## 残工数への影響

S0が両archで成立したため、残WBSはS1 **16〜26** + S2 **16〜26** + S3 **18〜30** + S4 **6〜12** + S5 **10〜18** = **66〜112時間**。S0確認後の条件付き残計画。日本語CMap同梱と型別表示/fixture来歴は既存S2/S3の依存/互換作業に含め、追加枠を二重加算しない。

既存R5/R6/M7 **28〜48時間**を加えた残計画は**94〜160時間＋未積算のM6監査残件**。任意ツール実接続8〜17時間を全採用する場合は**102〜177時間＋M6未積算残件**。S0計画8〜14を除くWBSで、人の実工数・節約・残予算ではない。runner約106秒やCI経過時間から開発工数を算出しない。

S1へは進まず、S0の結果と記録のcommit/pushまでで停止する。クラウド/公開/独立監査/外部連携は別枠のまま。
