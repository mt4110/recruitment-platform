# S2 鍵管理・隔離ワーカーの実装記録

状態：実装・局所検証を実施、最終CIの受入確認中。S3は未着手。

## 承認範囲と変更

S2の鍵管理、broker／relay／sandbox分離、復号権限・失効・障害時の拒否と処理復帰、E2E、CI、Git反映を対象とする。[実装契約](../design/14-s2-worker-contract.md)と[正本設計](../design/12-secure-document-pipeline.md)を参照。

- RSA-3072 OAEP/SHA-256の秘密操作はNode/OpenSSLだけで行う。原本／成果物、upload ticket、下書き、worker認証、AV認証、請求認証を別用途・別鍵で管理する。原本鍵はbrokerだけにmountし、API／Next／relay／sandboxへ渡さない。
- DBに版ごとの鍵identity、有効状態、新規wrapに使う版、管理操作の監査を保持。失効は再起動・setup・migrationで解除しない。ローテーションで旧原本／成果物鍵を保持し、欠落時は自動生成で代替しない。
- 毎回新しい3コンテナと2 internal networkを作り、実行後に全3コンテナを停止。非root、read-only、capability全drop、seccomp、CPU／メモリ／PID／scratch上限を適用。ホストの管理スクリプトが起動し、アプリへDocker権限を渡さない。
- APIのworker窓口をcontrol interface:8081に限定。利用者用8080はdefault interface／loopbackだけ。workerはDB資格情報を持たず、固定のジョブ制御関数を通す。
- 元受付・canonical attempt・本人／組織・候補者・鍵・120秒leaseを復号認可時と結果確定時に照合。古いtoken／generationの確定を拒否。インフラ障害はretryable、改ざん・AV検出・形式拒否はrejectedで7日結果保持へ進む。
- 実AVの鮮度／ロード世代／hashを照合してから、鍵のないrelayを通じて別sandboxの既存PDF／XLSX validatorを実行。AEAD tag照合完了前の平文を渡さない。
- S2の成果物は暗号化した検査manifestのみ。各generationに新DEK／nonce／成果物IDを持ち、原本hash・policy・org・版をAADへ束縛する。create_new／fsync／DB参照確定で差替えを防ぎ、孤児も容量予約に残す。
- 請求生成を専用サービス・専用認証鍵へ分離。旧検査サービスと互いのrouteを拒否する。請求PDFの外部表示を閉じる変更はS3。

検査合格の書類はchecked（変換待ち）で、documentsはpendingのまま。拒否時はdocumentsもrejected。安全な閲覧・推薦へ進むreadyを生成しない。原本名/hashは検証済みjobへ記録し、S3で変換・成果物受入後に公開metadataへ反映する。旧平文経路／請求PDF経路は残っており、外部公開・実情報利用を承認しない。

## 確認範囲の限界

120秒のlease失効はDB時刻fixtureで進める試験を含む。実際のbrokerプロセス停止／AV停止と区別する。鍵欠落は原本鍵の読取権限を一時的に拒否して確認し、原本秘密鍵のbyte列は変更しない。旧鍵の再読込みと成果物復号は検証用のホスト処理であり、利用者向けの復号APIではない。

S3のページ画像／代替テキスト／XLSX表示、成果物閲覧API・共有失効、S4移行、R5、公開は未実施。物理電源断・ディスク実満杯・ホスト侵害・独立セキュリティ監査を検証済みとはしない。新規のpackage依存は追加せず、既存の固定Node／Python inspectorを再利用した。M6全体監査の保留を解除したとは扱わない。

## 運用の入口

`python3 scripts/local.py setup` で既存設定を拡張し、`up`で追加migrationを適用する。欠落した既存鍵を別の鍵へ置換しない。今回、通常デモへのsetup／up／migrationは実行しない。

管理者が `python3 scripts/document_job.py` を1回実行すると、1件処理して停止する。自動の常駐処理ではない。`scripts/document_key.py` のenable／revoke／rotate／activateはローカル管理者の明示操作。鍵失効解除では過去の鍵漏えいを解消できない。削除や既存blobの上書きは行わない。
