## 対象の限定

これは既知脆弱性の機械照合とライセンス棚卸しであり、全実行経路の脆弱性不存在、侵入試験、法的な配布適合の保証ではない。イメージ内のlicense/copyrightを保持する。独自imageの一般配布に伴うGPL/MPL対応ソース・NOTICE等の最終確認と第三者再現はM7に残す。未知/未取得licenseを集計し、検出名だけで適合と扱わない。Chromiumおよびwheel同梱native libraryをOS package scannerが完全に識別する保証もないため、実versionと一次資料を別途記録する。

**監査gateは未合格。** 修正版ありのHigh/Critical検出はweb3、PDF7、DB25で残る。npmに同梱されたbrace-expansion/undici、PDF imageのsystem Python用msgpack/setuptools/urllib3、DB imageのGo製補助ツールのstdlib等。OS package upgradeだけでは同梱言語ライブラリを更新しない。製品APIでの到達性と修正方法は未確定で、機械検出を無害とみなさない。通常の業務E2E成功とは別の残件として保持する。

- API/Web/DBのCVE-2023-45853は[Debian公式](https://security-tracker.debian.org/tracker/CVE-2023-45853)がbookwormの対象binaryを生成しないと説明する。scannerはwill_not_fixとしてCriticalに含める。記録は消さず、vendor説明と実imageの経路の評価を分ける。
- DBとClamAVのCVE-2026-6653は[Debian公式](https://security-tracker.debian.org/tracker/CVE-2026-6653)でbookworm/trixieとも未修正（minor issue/no-dsa等）。ClamAVは入力ファイルを処理するため、ネットワーク隔離/非root/資源上限があっても残存リスクを0と評価しない。対処または利用範囲の判断が必要。
- DB imageのlibsqlite3とGo補助ツールの指摘、その他OS指摘はinventoryのversion/path/URLを保持。補助ツールであるという理由だけで自動免責しない。
- [RustSec](m6-2026-10-16/arm64/audit/cargo.json)は既知のrsa0.9.10/RUSTSEC-2023-0071が1件。APIはOIDC公開鍵検証のみで秘密鍵処理なしという従前の経路評価を維持するが、指摘0件・gate合格とは呼ばない。
- Web/E2E/PDF各lockのnpm auditは0、作業treeのTrivy secret scanも0。これをOS/同梱native libraryや全履歴の保証に拡張しない。
- package/license inventoryは未知または未取得licenseがarm64 534、amd64 535 packageあり、配布適合は未確定。全Cargo packageのlicense metadataも保存する。

arm64での[PDF実runtime](m6-2026-10-16/native-runtime.json): Python3.13.16、Expat2.8.5、qpdf12.4.2、wheelのlibxml2 2.14.6、Pillow native library、Chrome for Testing156.0.8078.4、Node24.22.0。[qpdf公式release notes](https://qpdf.readthedocs.io/en/stable/release-notes.html)、[Playwright Docker](https://playwright.dev/docs/docker)、[Chromiumの更新情報](https://chromereleases.googleblog.com/)を参照。wheelのnative版とDebian OS版は混同しない。scannerがChromiumやwheel内nativeを完全に照合した意味ではない。

Chrome for Testingの`ABOUT`とsandbox付き`chrome://terms`も実imageで開き、[観測metadata](m6-2026-10-16/browser-terms.json)を保存した。[Google公式の追加規約](https://www.google.com/chrome/terms/)は実行バイナリへ適用される。PlaywrightのApache-2.0表記だけでブラウザ全体の配布条件を判断しない。M7で独自imageの再配布条件を確認する。

Trivy DBは2026-10-16更新、Java DBも同日更新の版を用い、NextUpdate前であることを確認。DB更新で指摘は変化する。Trivyは[Aqua公式release](https://github.com/aquasecurity/trivy/releases/tag/v0.76.0)のchecksumと照合した。機械scanの[対象と限界](https://trivy.dev/docs/v0.76/guide/scanner/vulnerability/)を踏まえ、無視listは作らない。

## M6残件・残計画と停止

M6を無条件に完了扱いにしない。残るのは、(1)同梱npm/system Python/Go補助ツールの修正方針・更新、(2)vendor未修正のXML/SQLite/OS指摘の利用経路・隔離の評価と対処方針、(3)vendorが対象外とする指摘との照合と、その結果に沿う監査gateの判断根拠である。機械検出を一括無視する設定は加えない。特にClamAVの未修正XMLライブラリは、配布OS変更・自前build/patch・制約付き利用の選択に影響する。採る方式と実際の差分を決めてから追加見積もりする。

R5 12〜20 + R6 10〜16 + M7 6〜12 = **28〜48時間**の既存WBSが残る。これに**M6監査残件（未積算）**を加える。従前34〜60からM6枠6〜12を機械的に引いた値を、新しい総工数やM6完了と扱わない。人の実工数・節約量・残予算は未計測。監査で見つかった追加対応と、外部公開のTLS/OIDC/IP制限・接続検証は未積算であり、28〜48時間内へ無断で含めない。

今回の検証済み部分と残件をGitへ固定して停止する。R5、M7、CloudSign連携、通常デモへの更新、外部公開は未着手。OSSの独自image再配布条件の最終確認はM7へ残す。監査指摘を残したままの公開可否を代行しない。
