## 状態

## 変更

共通useDraftを利用するログイン以外の既存12 form_typeへ、AES-GCMの端末保存、pending mutationと業務送信予定の保存、オンライン再認証・現在権限確認後の復号・同期を追加した。フォームのレイアウト・装飾は変更していない。

local-drafts.tsはIndexedDB／暗号化／tab排他／終了マーカーを担当し、drafts.tsxはAPI同期と本人の選択を担当する。新規製品コードはTypeScriptで型検査する。既存本体CJSの全面TS化・Rust HTTP／業務／SQLの全面分離は今回含めず、厳密なClean Architectureの完成とは扱わない。新しい依存は追加していない。

初回オンラインでserver draft ID・期限を取得してから端末保存する。未初期化のまま通信断になった場合や鍵／storage取得失敗時は、耐久保存を保証せず入力を保持して警告し、業務確定を止める。サーバーの件数・容量・頻度制限を迂回しない。

端末ではorg/user・対象・draft・schema・版・期限・tab/seq・鍵版をAADへ含め、IVを毎回更新する。鍵は非extractableのメモリ参照だけに持つ。Web Storageにはランダムなtabラベルだけを保持し、本文・鍵・認証情報を置かない。ファイル本体・署名ticket・DEK・確認済みフラグは保存しない。

複製タブのlabel衝突は[Web Locks](https://www.w3.org/TR/web-locks/)で回避する。非対応環境では新IDを使い、同一tabの自動選択を保証せず本人が候補を選ぶ。端末recordがまだなくてもdraft単位のterminal markerを保存し、IDB writeと同一store transactionで照合する。consume/discard後の遅延書込みで本文を復活させない。

業務送信予定は確認フラグを除いた入力・元version・要求hash・元operation IDとして暗号化し、保存後だけ送る。応答喪失後はoutcomeを先に照合し、committedは認可された結果へ移動、not_recordedは本人の再確認と同一hash・同一IDでだけ再試行する。7日後・失効・404を未実行と見なさない。

## 対象フォームと保存の境界

| form_type | 共通処理への接続 | 保存／復元する入力 |
| --- | --- | --- |
| job_new / job_edit | business.tsx | 求人名・仕事内容・勤務地・雇用形態 |
| candidate_new / candidate_edit | business.tsx | 氏名・経歴概要。架空確認は保存しない |
| application_new / application_reason | applications.tsx | 候補者選択・候補者検索・推薦理由 |
| application_submit | applications.tsx | 選択書類ID・元の候補者／求人版。同意は保存しない |
| selection_note | applications.tsx | 選考／辞退／共有撤回の操作種別・理由 |
| document_upload | documents.tsx | 種類・登録待ちmetadata・元キー・受付ID。Fileは保存しない |
| job_filters / candidate_filters / application_filters | business.tsx / applications.tsx | 検索・絞込み・cursor等 |

12種の接続はソースと既存全体回帰で確認し、R5追加14件では共通の暗号化・通信断・再起動・確定競合を重点確認する。各form_type×全障害×全端末を総当たりしたという意味ではない。focus／scrollは対応するname属性のあるfieldを復元し、ファイル選択や確認項目の復元へ流用しない。

## 検証と限界

Browser plugin not availableのため、既存Playwrightの隔離環境・Chromium PCを使用する。同じpersistent profileの実ブラウザプロセスを閉じて再起動する。単なるreloadや別incognito contextを同一profile再起動と呼ばない。

追加ケースは、通信断→暗号文→プロセス再起動・再認証・同期、確定応答喪失の結果復帰、別本人、旧鍵再暗号化／失効拒否、改ざん／サーバー期限、保存例外、2タブ、未確定要求の本人再試行、consume後の遅延暗号化、保存mutation応答喪失、opener付き複製タブ、端末初回保存前のdiscardとの競合、フォーム終了後の一覧からの結果照合、初期化・blur・debounce・PUTの直列化と最新入力の維持。既存の組織RLS・全schema・upload結果・共有失効・請求・S4復旧も全体回帰で確認する。

通信断・暗号化遅延・保存例外は試験用の注入。期限切れは隔離DBの時刻fixtureであり、実際の7日経過やOSのディスク枯渇を再現したものではない。実機iOS／Safari、OS電断、サイトデータ消去、端末故障、ログイン中XSS、別端末への未同期入力の転送は保証対象外。復元できるのは最後にIDB transactionの完了を確認した内容まで。

### 修正と再確認

- 初期化時の直接保存を共通キューへ統合し、遅い鍵取得・blur・debounceが重なっても保存を直列化する。確定前のdraft IDを保持し、確定後の遅延書込みで復活させない。
- 再認証照合中は表示・復号・送信を停止し、401で業務フォームを外す。推薦の明示再読込は現在版で新規下書きを開始する。求人／候補者の外部更新によるcontext競合も入力を保持して明示再読込へ誘導する。
- 競合試験は初期保存完了→外部更新→追加入力→保存の順で再現する。先行native試験の「外部更新前に入力済み」では既に自動保存が終わる場合があり、期待する競合が発生しなかった。安全条件を変更せず試験順序を修正した。
- 応答喪失試験は実際の応答本文を確保してから切断し、同一operation ID・結果照合・重複作成なしを確認する。M5の409は要求UUID・DRAFT_TERMINAL・DBの終了状態を応答前に照合し、未証明の応答は失敗とする。
- M5では隔離scannerを意図的に停止して503・利用不可・検査実績なし・原本410を確認する。復帰後に画面の既存再試行を選び、同じ受付ID・書類1件・upload POST1回のまま選考→採用→請求HTML・未送信通知まで進む。APIのscanner timeout23秒に合わせ、当該応答の待機を35秒とした。全体／各テストのtimeoutは拡張していない。
- R2の定義切替時503はSCANNER_UNAVAILABLEだけを受理し、配信拒否を確認後、準備完了を待って同一IDで1回だけ再試行し、ロード世代一致を確認する。S5の不正形式検査は基盤由来の再試行可能状態を1回だけ復帰し、最終FORMAT_REJECTEDを必須とする。途中の利用不可・document_artifactsが0件も確認する。AVだけが原因、全種類の派生物が存在しない、とは断定しない。
- 件数・頻度のfixtureは隔離試験の蓄積だけをrevision付きで期限切れ／経過扱いにし、行・暗号文を保持する。製品の50件・新規30回/時・更新120回/分は緩和しない。R4の上限拒否も維持する。

各採用runの開始時clean・途中ソース不変・終了後停止を確認した。Rust単体9件、TypeScript型検査、Python／Node構文検査も確認した。AV3サービスの稼働・OOMなし、11サービスの機密ログ検査はrunner記録に残す。対象52件の全3環境でS4の旧鍵・backup復旧、選択版維持、移行後の認可を再確認した。原本・cookie・鍵・生ログ・browser profileは配布物へ含めない。
