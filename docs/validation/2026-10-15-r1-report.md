# R1実装・検証結果 — 2026-10-15

## 結果と境界

**R1の実装・arm64ローカル/最終Linux/amd64 CIの確認を完了。記録をcommit/pushしてR2へ進まず停止する。** 対象sourceは `194e2b99198e9d0f657c816c1f8575720b899a75`。最終記録のcommitは検証済みsourceから文書/証拠だけを追加する。

PDF/XLSXの形式検査、書類metadata、DB/API、原本/共有/推薦の利用可否、旧PDFの追加migrationを実装した。**R1はAVを実装しない。形式合格だけでは202/pending・available=falseで、ダウンロード/推薦に使えない。** 旧ready PDFもAV記録なしなら利用不可。製品用のAV mockや許可flagは追加していない。

検証は新しい隔離Compose環境で実行した。通常デモ`localhost:3000`のM4環境・DB・既存volumeは更新していない。通常デモへの反映と、実AVを使った正常系の一巡は未実施であり、本番運用の成立を示す記録ではない。

### R2への境界をDBでも維持

R1の`app_runtime`はdocument_checksへSELECTだけ。INSERT/UPDATE/DELETEを与えず、形式検査APIがAV cleanを自作できない。document_usableは呼出し元のRLSで評価し、SECURITY DEFINERによる原本権限の迂回を作らない。R2は認証付きscan応答のnonce/hash/世代/鮮度を照合するwriterを追加する必要がある。

正常系の原本・共有配信とM4回帰には、隔離test DBの管理接続から明示的な`TEST_ONLY_SYNTHETIC_NO_AV`記録を投入した。これは実ウイルス検査の証拠ではない。raw uploadがAV待ちとなり配信を拒否する試験と、合格記録が既にある状態での配信/RLS試験を分けた。

### 確認した主要な境界

- 新規PDF/XLSXの形式合格でも、AVなしの原本/推薦提出を拒否。旧readyと既存共有snapshotもAV記録なしなら拒否。
- 他agency・他employerの直接ID、原本、共有、upload/retry/recheck/outcomeを拒否。公開求人と自社候補者の既存RLS、snapshot不変性、共有失効も回帰確認。
- synthetic cleanがある場合のXLSX attachment、同じbytes、MIME/固定名を確認。blocked追記がcleanに優先し、失効後employerはchecksも読めない。
- 7日間の失敗結果と同キー再送で期限を延長しない。期限後の照合・不正multipartでの同キーPOSTも409となり、結果詳細/新規documentを返さずtombstone化。processingは同じIDへ復帰する。
- 元0001〜0005のSQLは変更せず、実際に0005までのschemaへ架空ready PDF/共有参照/旧結果を作ってから0006を適用。旧列・snapshot・原本hashを比較し、旧期限から6日加算されたことを確認。
- XLSX: 正常な実Sheets2点、許可式と内部参照、Print_Area/Print_Titles、拒否式/DDE/外部参照、未知part/namespace、NUL/重複/衝突/path逸脱/symlink/入れ子、展開比・entryサイズ/数、XML深さ/要素数、壊れた画像などを実workerで確認。

## 検出・修正した問題

| 発見 | 対応と確認 |
| --- | --- |
| 旧R0試料のPNG CRC不正 | 検査は緩めず旧2点を保持。builderのPNGを直し、Sheetsへnative import→native XLSX exportした新2点をe2e/fixturesへ追加。旧試料は拒否、新試料は合格 |
| 未使用namespace宣言 | R0の棚卸しは使用要素中心だった。Sheetsが宣言する13 URIを宣言だけの例外に列挙し、実要素/属性/partへは許可を広げない。未知宣言とVML要素を拒否 |
| ZIP名のNUL切詰め | 元の検査が受理するケースを再現。ZipInfoの元名と処理名を照合し拒否へ修正。NFC正規化も実装。NUL・大文字小文字衝突・不正sheet名を試験で拒否 |
| FORCE RLS下の期限backfillが0件 | 移行トランザクション内だけのmigrator policyで旧uploadを更新し、commit前にpolicyを除く。runtime権限は広げず実移行で6日加算を確認 |
| 先行試験のsynthetic記録が集計へ混入 | org全体ではなく当該候補者の記録0件を確認する試験へ修正。配信拒否の期待値は維持 |
| selectのlabel探索 | visible labelをhtmlFor/idで明示し、ブラウザ選択/focusを確認 |
| 旧画面のdownload可能という説明 | 現在のAV待ちへ修正し、無効な再試行操作も表示しない |
| Docker自動address pool枯渇 | 過去環境を削除せず、新規E2E専用の未使用/27 subnetを選択。通常デモのネットワークを変更しない |
