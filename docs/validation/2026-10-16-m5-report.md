# M5 通知モック・固定1ページ請求PDF

2026-10-16。M5のみを実装。R5、クラウドサイン連携、公開設定、M6/M7の配布監査/第三者確認は行わない。検証対象commitは`d323598bc6bf58895ca9fb55467208a6db656c49`。arm64とLinux/amd64の全件回帰を完了した。M5のローカル一巡を受け入れ、公開は別判断にする。

## 見せられる業務の一巡

求人企業の求人登録/公開 → 紹介会社の求人確認 → 架空候補者/検査済み書類の登録 → 共有版を選択した推薦提出 → 企業の選考/採用決定 → 固定1ページのデモ請求PDF表示。状態変更の相手組織宛て通知を「未送信のデモ」として画面で確認できる。実メール・外部請求・決済・契約送信はない。

## 実装内容

- `GET /notifications`は既存`notification_previews`の通常RLSを使い、宛先組織の記録だけを表示する。cursor/limitのみ、最大100件。カーソルにorg・件数・日時・IDを含め、別orgへの流用を拒否する。任意org指定や未知項目は422。bodyは既存の固定デモ文で、候補者の氏名・経歴を載せない。書込み/送信APIは作らない。
- `GET /applications/:id/invoice-preview`と`.pdf`を追加。hiredとplacementの存在、およびA_OWNERまたはE_SHAREDを通常runtime/RLSで確認する。DTOは番号/日付/宛先/発行者/金額/税/デモ注意のみ。企業の共有失効後は404、紹介会社は引き続き表示可能。表示の繰返しでplacementを作らない。
- 採用決定日はDBの日本時間で日付化し、番号は`DEMO-{placement_id}`。固定500,000円・税額「未計算」・1明細・A4縦1ページ。候補者情報、支払い先/期日/登録番号を出さない。デモ注意を上/下に表示する。
- 正本の組織名は推薦時のsnapshot。画面では全文、PDFではIntl.Segmenterの書記素で最大40（省略記号を含む）・各2行へ制限。文字列をHTML escapeし、任意HTML/URL/明細を受け付けない。
- PDF serviceに内部共有鍵で認証する生成endpointを追加。Playwright/ChromiumはM0と同じ1.62.1の公式image digest/lockを利用し、Noto CJK・Popplerを同梱。Python依存のwheel hash固定を維持。専用内部network・非root・read-only・cap drop・namespace用SYS_CHROOT・M0で確認済みseccomp policyを明示する。ブラウザのsandboxを無効化せず、各生成時にnamespaceとSeccomp-BPFを検査する。
- PDF serviceは同時1worker、生成8秒（終了処理を含む上限は別）、コンテナ1536MiB/2CPU/256PID、tmpfs/shm各256MiB。外向き通信を持たないnetworkと全リクエスト拒否のブラウザrouteを併用。フォント読込、組織名/フッターの収まり、生成後のpikepdf page count=1/A4を検査する。Python親はtimeout時にNodeへ終了を通知し、Nodeはbrowser.closeを行う。
- APIは生成をDB transactionの外で実行し、生成後に再認証と請求の現在の認可・内容を再確認する。内部PDFのContent-Type/長さ/先頭を確認し、最大512KiB、inline/no-store/nosniffで返す。障害時は503、API要求timeoutは504。再試行ボタンを設ける。
- 画面は認証失効、共有失効または共有状態の確認失敗時にPDF blob URLをrevokeし、全文組織名を含む表示を消す。PDF原本をブラウザ永続ストレージへ保存しない。取得済みの書類を相手の端末から回収できる保証ではない。
- 新規入力フォームとDB migrationはない。既存フォームのR4契約を維持し、R5のIndexedDB/オフライン端末同期には進まない。

## 局所検証と修正履歴

ビルド時にrendererのDocker context許可リストへnpm lock/生成workerを追加した。Rustの既存HTTP依存はJSON送信featureを持たないため、依存追加せず既存serde_jsonでbodyをシリアライズした。局所の停止試験はNext.jsのroute announcerまでalertとして拾ったため、業務領域にlocatorを限定した。後続の試験を前の画面状態に依存させず、それぞれ対象を開いて確認するよう修正した。

局所7件は成功。ブラウザ用イメージのsystem Python 3.12/Expat 2.6.1で既存XLSXの最低パーサー条件を満たせず、最初の全件実行は事前検査で停止した。従来の固定Python imageの/usr/localを別stageから組み込み、3.13.16/Expat 2.8.5と既存67ケース・sandbox付き請求生成のpreflightを確認した。パーサー条件は緩和していない。該当CI 38845811311は打切り。その後の9件試験は、再利用したR4検証DBでブラウザ書類登録の完了待ちが失敗した（8/9）。これを全件受入に使わず、新規隔離DBで最終回帰を行う。ログ上の事実と原因が確認できた範囲だけを記録し、検査条件やquotaを弱めない。

先行commit 3edefbaはarm64全97件成功、CI 38846213899は96/97成功。共有失効404が遅れてconsoleへ届き、afterAllで想定外とされた。失効した対象URLとHTTP状態だけを継続して識別する形にテストを修正し、無関係な404/他のエラーは引き続き失敗にした。製品コードは変えず、最終ソースで両archを再実行し、下記の最終受入を完了した。

追加E2Eは9件。本人/組織・非採用拒否、notification RLS/cursor、ブラウザ一巡、長名/特殊文字、停止/復旧、共有失効、内部生成schema/認証、セッション期限後の表示消去を扱う。長名/特殊文字のfixtureは組織名を設定して通常業務で新しいsnapshotを作り、保護triggerは無効化しない。PDFは両参加者で取得してpage count/A4/フォント/日本語・固定額/注意文2箇所/候補者本文なしを確認し、PNGで目視する。

Playwrightの公式仕様（[sandbox設定](https://playwright.dev/docs/api/class-browsertype#browser-type-launch-option-chromium-sandbox)、[PDF生成](https://playwright.dev/docs/api/class-page#page-pdf)、[Dockerの隔離](https://playwright.dev/docs/docker)）を確認した。npm auditの今回のPlaywright lockは既知指摘0件。これをOS/Chromium/native libraryを含む包括的監査とは扱わず、M6の配布物監査を残す。

## 先方限定公開に進む前の確認

**現行実装はlocalhost専用で、そのままトンネルを立てて外部公開する状態ではない。** `services/api/src/auth.rs`はAPP_ORIGINを`http://localhost:{port}`、issuerをローカルIdPへ制限し、CookieもSecure=falseにしている。リバースプロキシの入口だけIP制限しても、公開側のログイン/redirect/CSRF設定が自動で整うわけではない。

次段階で、先方の固定グローバルIP（IPv4/IPv6・VPN経由・出口変更時の扱い）、公開ホスト名、接続期間/停止担当、本人用デモアカウントの配布方法を確認する。HTTPS origin/issuer/redirect/Cookie Secureを対応し、信頼するproxy headerを限定する。アプリとIdP両方に同じ公開範囲を適用し、別経路での直接アクセスを閉じる。レジュメと請求PDFをCDN cacheへ載せず、デモ専用DB/資格情報を通常デモから分離し、IP拒否/ログイン/CSRF/ファイル取得を公開経路で再検証する。常時起動やPCのsleep、容量、AV定義更新、停止/復旧も確認する。

Cloudflare/ngrokの選定・アカウント設定・公開・課金は未実施。M5の技術成功を公開承認や本番適性の証明にしない。R5の未同期端末保存がないことも、デモ利用者へ明記する。
